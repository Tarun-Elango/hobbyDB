kestrelKV

by Tarun-Elango

A distributed key-value store in Go — Raft consensus, a durable write-ahead log, and a custom binary TCP protocol for clients and peer replication.

Why kestrelKV?

  • Raft consensus — nodes elect a leader automatically; no node is hand-picked, and a new leader takes over when one dies
  • Durable writes — every command is fsynced to the WAL before it is acknowledged
  • Persistent Raft state — the current term and vote survive restarts, so a node never votes twice in one round
  • Custom binary protocol — a compact TCP protocol for clients and for replication between peers
  • Smart client — writes sent to a follower are retried on the leader, and the client follows the cluster through failovers
  • Tested under failure — multi-node correctness and fault-tolerance tests covering crashes and partitions

Requirements

  • macOS or Linux (amd64 or arm64)
  • Go 1.26+ to build from source

A cluster is three nodes, each with its own client port, replication port, and WAL file. Everything runs locally — no hosted service.

Quick install

Install a prebuilt server binary from GitHub Releases, run the following from the repo:

./deploy/install.sh

This installs kestrel to /usr/local/bin and creates a WAL directory at ~/.kestrel. More install options

Client commands

  • set <key> <value> — store a value
  • get <key> — read a value
  • del <key> — delete a key
  • len — number of keys in the store
  • ping — check the connection
  • quit — exit the client

Cluster layout

Three nodes. Run each in its own terminal, then use a fourth for the client. Run commands from the repo root.

NodeNode IDClientReplication
Node Anode-a:9000:9001
Node Bnode-b:9010:9002
Node Cnode-c:9020:9003

Raft elects the leader automatically. Pass every node's client address in -client-peers so a follower can hand the client the leader's address.

Run the nodes

Every node starts as a follower until it wins an election. -verbose turns on logging (drop it for a quiet node). Add -pprof-addr=127.0.0.1:8080 for profiling, using a different port per process.

Node A — :9000 
cd cmd/server
go run . \
  -node-id=node-a \
  -verbose \
  -client-addr=:9000 \
  -replication-addr=:9001 \
  -wal=data/node-a.wal \
  -peers=node-b=127.0.0.1:9002,node-c=127.0.0.1:9003 \
  -client-peers=node-b=127.0.0.1:9010,node-c=127.0.0.1:9020
Node B — :9010 
cd cmd/server
go run . \
  -node-id=node-b \
  -verbose \
  -client-addr=:9010 \
  -replication-addr=:9002 \
  -wal=data/node-b.wal \
  -peers=node-a=127.0.0.1:9001,node-c=127.0.0.1:9003 \
  -client-peers=node-a=127.0.0.1:9000,node-c=127.0.0.1:9020
Node C — :9020 
cd cmd/server
go run . \
  -node-id=node-c \
  -verbose \
  -client-addr=:9020 \
  -replication-addr=:9003 \
  -wal=data/node-c.wal \
  -peers=node-a=127.0.0.1:9001,node-b=127.0.0.1:9002 \
  -client-peers=node-a=127.0.0.1:9000,node-b=127.0.0.1:9010

Client

Connect with every client port. A write sent to a follower is retried on the leader, and a dead leader is replaced by whichever node wins the next election.

cd client
go run . --9000 --9010 --9020

Examples: set foo bar, get foo, del foo, len, ping, quit.

WAL files

Compare WAL files

From cmd/server after some writes. No output from cmp means the files are identical.

cmp data/node-a.wal data/node-b.wal
cmp data/node-a.wal data/node-c.wal

Inspect WAL bytes

xxd data/node-a.wal | head
xxd data/node-b.wal | head
xxd data/node-c.wal | head

Raft metadata (term and vote) is stored separately, e.g. data/node-a.wal-raft.state.

Install from a release

deploy/install.sh installs a prebuilt server binary from GitHub Releases (Linux or macOS, amd64/arm64).

./deploy/install.sh          # latest release
./deploy/install.sh v0.1.0   # specific version

It downloads the binary for your OS/CPU over HTTPS, verifies its SHA-256 checksum, and installs it to /usr/local/bin/kestrel (using sudo only if needed). It creates a WAL directory at ~/.kestrel (/var/lib/kestrel as root). It does not start the server; run kestrel with your own flags, e.g. --wal=$HOME/.kestrel/node-a.wal.

Uninstall

kestrel-uninstall --purge

Without --purge it removes the binary but keeps the WAL directory.
